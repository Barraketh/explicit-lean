# T6 multiple-invocation rendering design

## Decision

Recommend a branch-aware structural expansion in T4.  The renderer should
materialize the source tactic's branch tree into ordinary Lean bullets and put
the trace for invocation `k` at leaf `k`, in Lean's deterministic goal-creation
order.  This gives a direct invocation-to-goal mapping; it does not match
pretty-printed goals, try alternatives, or search hypotheses.  It requires a
small clarification to the PLAN rendering rule for non-tail sites (the current
`first` prescription is not a safe substitute for an invocation mapping).

No new trace schema is needed beyond the already specified `invocation` and
`invocations` fields, but T1 must emit them.  A legacy trace set without those
fields is not safe to replay and is structurally refused, rather than inferred
from filenames or deduplicated by step content.

## Rendering algorithm

1. **Group and validate.** Group traces by the stable source site key
   `(module, occurrence)` (or the source range used by the trace producer).
   Require exactly one `invocations = n` value and exactly the ordinals
   `invocation = 0, ..., n-1`; reject duplicates, gaps, mixed counts, missing
   metadata, or a trace count inconsistent with the source branch leaves.
   Never infer multiplicity from filenames and never collapse equal step lists.

2. **Parse the enclosing tactic spine.** Identify the smallest enclosing
   `<;>` tree whose rightmost leaves contain the traced call.  Recognize the
   branch-producing forms present here (`by_cases`, `rcases`, `obtain`) and
   preserve their binders and branch order.  For a single branch-producing
   prefix, replace
   `t <;> simp_trace [...]` with `t` followed by one bullet per leaf.  For
   nested `<;>`, recursively expand the tree, so group C becomes nested bullets
   and group D becomes four leaves in the order generated by Lean.

3. **Keep the original adjacent.** Emit the original `simp [...]` syntax as a
   comment immediately above the generated branch tree.  The generated leaves
   contain only the ordinary `explicit_rw` step list (and any permitted
   readability post-pass such as `rw`/`exact`/`change`).

4. **Handle a non-tail call.** If tactics follow the traced call in the same
   `<;>` chain, expand the branch tree and copy that already-existing suffix
   into each corresponding leaf.  For the `Function/Defs.lean:139` reproducer,
   the shape is:

   ```lean
   -- Original simp: simp [h]
   by_cases h : a == b
   · explicit_rw [/* invocation 0 */]
     simpa [I.eq_iff] using h
   · explicit_rw [/* invocation 1 */]
     simpa [I.eq_iff] using h
   ```

   This preserves tactic sequencing without asking a later tactic to rediscover
   which branch a trace belonged to.  The suffix is outside T6's replacement
   semantics and remains byte-for-byte equivalent modulo indentation.

5. **Optional compact form.** Keep `t <;> explicit_rw [...]` only when the
   source AST proves that there is one direct leaf per invocation, all `n`
   traces are complete, and their step lists are identical.  This is a
   formatting optimization, not the identity mechanism.  Do not use
   `<;> first | explicit_rw [...] | ...` as the general implementation: an
   alternative can succeed on a different branch, and `first` then silently
   loses the ordinal-to-goal correspondence.  If the PLAN rule retains this
   form for compatibility, it must be guarded by a proof of branch-specific
   failure or marked structurally refused.

6. **Validate the mapping.** Before calling a site replayed, verify that the
   generated branch tree produces exactly `n` leaves and compile the complete
   declaration/module.  The status is `replayed` only if every ordinal's
   explicit steps and the enclosing declaration compile.  A failed one makes
   the whole site unresolved; do not report partial replay.

## Status boundaries

- **Replayed:** metadata is complete, the source branch spine is recognized,
  every ordinal is rendered exactly once at its corresponding leaf, and the
  complete declaration compiles with no forbidden executable replacement token.
- **Unresolved:** the trace is well-formed and structurally mapped, but an
  ordinal has an unsupported step, an elaboration/compile failure, or an
  unresolved close.  Retain the original call with the required marker and
  report the ordinal and exact failure.
- **Structurally refused:** invocation metadata is absent/inconsistent; the
  source cannot be parsed into a one-to-one branch spine; a tactic creates or
  reorders goals in a way not represented by the trace; or expanding a
  non-tail chain would change scope/semantics.  Retain the original call and
  distinguish this from an explicit replay failure.

## Alternatives and trade-offs

1. **Recommended: structural branch expansion.** Direct bullets are ordinary
   Lean, readable, deterministic, and work for nested `<;>`, `by_cases`, and
   `rcases`. They may duplicate a suffix and require a small PLAN clarification,
   but they do not search or depend on pretty-print stability.

2. **PLAN-compatible `first` alternatives.** Render one `<;> first | ...`
   list in ordinal order, with comments naming each branch. This is compact and
   needs less source surgery, but selection is proof-success search rather than
   invocation mapping; identical or overlapping positional prefixes can choose
   the wrong trace. It is acceptable only as a guarded optimization, never as
   the fallback for an unrecognized branch tree.

3. **Runtime dispatch by goal fingerprints.** Add a generated dispatcher that
   compares `pre`, hypotheses, or branch context and then invokes the matching
   step list. This adds unstable pretty-print/context identity to the replay
   contract, is search by construction, and current traces do not carry enough
   context. It would require a schema change and is rejected.

## T4 acceptance fixtures

T4 should add focused fixtures for one member of each group (including the
non-tail Function/Defs case), plus a nested `<;>` fixture with two identical
step lists. Each fixture must assert: original comment adjacency; exact leaf
count and ordinal order; no filename/content deduplication; successful compile
of all leaves; and refusal for missing, duplicate, or gapped invocation
metadata. Run the existing pipeline checks and the six-module harness after the
fixtures pass. A failure in any one leaf keeps the source site unresolved.
